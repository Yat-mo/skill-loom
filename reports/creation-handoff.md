# Skill Loom v3.0.1 Creation Handoff

## Result

- Skill: `skill-loom` 3.0.1, owned by Yat-mo
- Job: turn recurring workflows, rules and source materials into researched, trigger-aware, evaluated and safely publishable Agent Skills
- Identity change: repository, public brand, Skill ID, adapters and self-validation moved from `qiaomu-meta-skill` to `skill-loom`
- Migration: the old name remains only as a legacy activation alias, upstream attribution, historical evidence or Qiaomu-owner profile compatibility

## Naming evidence

- Rejected `SkillForge`: multiple mature Agent Skill projects already use the name.
- Rejected `SkillSmith`: several skills and repositories already publish under that identity.
- Rejected `SkillFoundry`: multiple agent authoring toolchains already use it.
- Selected `Skill Loom`: low collision in the Agent Skill catalog, clear metaphor for weaving rules and workflows into a tested package, and available under `Yat-mo/skill-loom`.

## Reference skills studied

- `joeseesun/qiaomu-meta-skill`: direct upstream and source lineage; preserved attribution and semantic sync policy.
- `yaojingang/yao-meta-skill`: Skill IR, evidence boundaries, review layers and lifecycle gates.
- `joeseesun/qiaomu-skill-publisher`: idempotent profile handling, repository/skill identity separation, discovery and isolated installation.
- `WoJiSama/skill-based-architecture`: progressive disclosure, activation over storage, route rematching and principle-plus-check rules.

## Absorbed and rejected

- `keep`: prior-art research, proportional structure, trigger/output evaluation, evidence-bound claims, safe release and installation proof.
- `adapt`: brand-neutral package language; Qiaomu profile support remains only for explicitly Qiaomu-owned downstream packages.
- `reject`: a cosmetic title-only rename, reused `v2.x` identity, empty full scaffolds, direct default-branch pushes and unsupported quality claims.
- `invent`: the Skill Loom identity, migration alias, v3 Skill IR schema and README narrative that connects source material, structure and quality gates through the loom metaphor.

## Advantages and evidence

- `design advantage`: repository, Skill ID, adapters, installer command and validator now use one canonical identity.
- `design advantage`: README leads with user outcome, installation, concrete triggers and output before architecture detail.
- `design advantage`: the README now explains Agent Skill and Skill Loom in plain language before showing installation, files or validation terms.
- `validated advantage`: package, unit, trigger, release and clean-install results are recorded by the v3.0.1 release workflow.
- `hypothesis`: the shorter brand and product-first README should improve recall and adoption; conversion or user-comprehension evidence remains `missing evidence`.

## Verification boundary

- Deterministic package validation, unit tests and trigger eval must pass before publication.
- PR, Release, remote discovery and isolated installation are not evidence until the release workflow completes.
- Provider-backed output quality and human longitudinal comparison remain `missing evidence`.
